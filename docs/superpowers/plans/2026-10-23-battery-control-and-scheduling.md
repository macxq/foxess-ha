# FoxESS Battery Control and Mode Scheduling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement battery State-of-Charge (SoC) management, inverter work mode selection, scheduler toggle, and a schedule automation service in `macxq/foxess-ha` via the official FoxESS Cloud OpenAPI.

**Architecture:** Extend `FoxESSApiClient` with asynchronous write/read endpoints using `aiohttp` and MD5 request signatures. Move coordinator lifecycle to `__init__.py` so that `sensor`, `select`, `number`, and `switch` platforms share a single update coordinator. Entities for battery and scheduling are conditionally created only when `hasBattery` is detected, protecting PV-only installations.

**Tech Stack:** Home Assistant Core (Custom Component), Python 3.12+, `aiohttp`, `voluptuous`, `pytest`, `pytest-homeassistant-custom-component`.

**Spec:** [docs/superpowers/specs/2026-10-23-battery-control-and-scheduling-design.md](file:///Users/maciek/dev/foxess-ha/docs/superpowers/specs/2026-10-23-battery-control-and-scheduling-design.md)

## Global Constraints

- FoxESS OpenAPI 1-second rate-limit guard (`wait_for_api()`) must be respected on all write and read requests.
- All requests use HTTP `POST` with JSON bodies and signature headers generated by `GetAuth()`, except battery SoC get which is `GET`.
- PV-only systems (`hasBattery == False`) must never instantiate `select`, `number`, or `switch` entities.
- All entities must associate with the inverter's `DeviceInfo` (`(DOMAIN, deviceSN)`).
- 100% test coverage using `.venv/bin/pytest`.

## Review Focus

1. **Nighttime startup / offline inverter:** If the physical inverter is asleep during Home Assistant restart, the integration must rely on cached `entry.data["has_battery"]` or cloud device details to avoid dropping battery entities.
2. **Scheduler conflict on work mode change:** Attempting to switch `Work Mode` while the `Mode Scheduler` switch is active must be cleanly rejected with a `HomeAssistantError` instead of crashing with FoxESS error 44096.
3. **Cross-entity SoC clamping:** If a user sets `Min SoC` higher than `Min SoC on Grid`, the integration must clamp `Min SoC on Grid` to match before submitting to prevent cloud validation errors.
4. **Schedule service auto-enable:** Calling `foxess.set_schedule` with default parameters must automatically turn on the inverter's scheduler flag so cheap night charging automations take effect immediately.
5. **Rate-limit / network error resilience:** If FoxESS Cloud returns an error or times out during a write action, the entity must log a clear warning, raise `HomeAssistantError`, and preserve current state.
